# Engineering OS — Code Patterns

## Pipeline-First
Every task enters the pipeline. No code is written, reviewed, or delivered outside of the 13-phase pipeline. The pipeline TODO is the single source of truth for what's being worked on and where it is in the lifecycle.

## Agent Delegation
The auto agent never writes code directly. It analyzes the task, selects the appropriate specialized agent(s), delegates via the task tool, and only touches files when synthesizing results or managing TODOs. This prevents context corruption and ensures each agent works within its expertise.

## Gate Verification
Every phase transition requires passing a quality gate. Gates are explicit checks (not assumptions) that validate the phase output meets the entry criteria for the next phase. Example: you cannot move from implementation to review without the code compiling and linting passing.

## Context Engineering
The context engine builds a dependency graph of the project (architecture → packages → files → symbols). When an agent receives a task, it queries the context engine for only the relevant slice of the graph, avoiding full-project context bloat. Context is proactively loaded and aggressively pruned.

## ADR Every Decision
Every architecturally significant decision gets an ADR in memory/decisions.md. ADRs are auto-generated by the architect agent and reviewed by the debate cycle. No silent decisions.

## Parallel Execution
Independent phases (e.g., backend + frontend implementation) execute in parallel. The planner identifies dependency DAG and dispatches to multiple agents concurrently via task tool.
