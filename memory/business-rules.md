# Engineering OS — Business Rules

## Pipeline Completion Rule
No code is ever delivered without completing the full 13-phase pipeline. Skipping phases is forbidden. If a phase is not applicable, the gate for that phase must be explicitly marked as waived with a documented reason in the pipeline log.

## Delegation Rule
The auto agent NEVER implements code directly. It identifies the task, selects the appropriate specialized agent, and delegates via task tool. Violation: any direct file modification by auto agent outside of pipeline TODO management or result synthesis.

## ADR Rule
Every architecturally significant decision must have an ADR in memory/decisions.md. Significance includes: new dependency, new package, framework choice, API design, schema changes, infrastructure changes. Auto-generated by architect agent, reviewed by debate cycle.

## Feature Completeness Rule
A feature is complete only when all checklist items pass: build, lint, types, tests, coverage threshold, performance budget, security scan, code review, smoke test. No exceptions for "minor" changes.

## Quality Gates Order
build → lint → typecheck → tests → coverage → performance → security → code review → smoke test. Gates run in order. If any gate fails, the pipeline halts and requires correction before proceeding. No force-past.

## Single Source of Truth
Pipeline TODO is the authoritative record of what's being worked on. Context memory files are the authoritative record of project knowledge. Code is the authoritative record of implementation. No duplication between these.

## Immutable Memory
Memory files in memory/ are append-only. Previous content is never deleted, only supplemented with ADRs, lessons, or deprecation notices. This preserves decision history and reasoning.

## Token Economy Rule
Every model-bound context built by the agent system must honor cache-safe layering: stable layer (L0, byte-identical prefix) → semi-stable (L1) → volatile (L2). Violations of byte-exact prefix ordering raise CacheOrderViolation. Budgets are enforced per level (session/agent/subagent) with watchdogs at 0.8/0.9/1.0: >=1.0 returns stop, >=0.9 returns finalize, ratio NaN becomes 1 -> stop. Metrics (requests, tokens, cost, cache hit rate) persist to ~/.opencode/token-economy.json and feed the advisory token-economy gate. The engine is advisory by design — it never blocks generation; the tool/gate surface reports, the compaction path records real model usage.
